# Anti-slop Audit 001

- Tanggal: 2026-11-09
- Mode: AFTER (audit project yang sudah jadi)
- Scope: UI renderer `src/renderer/src/` (views, components, styles.css, index.html)
- Metode: inspeksi statis kode (app tidak dijalankan; tidak ada display di lingkungan audit). Kontras warna dihitung dengan formula WCAG 2.1, lihat lampiran.
- Brand direction dari owner (sesi 2026-11-09): modern minimalist, clean, professional; jiwa brand: kenyamanan dan kemudahan (comfort and ease).

Prioritas mengikuti tier aturan antislop: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## Ringkasan

Secara umum aplikasi ini jauh di atas rata-rata output AI: tidak ada statistik palsu, tidak ada testimoni fiktif, tidak ada buzzword marketing, semua kontrol interaktif punya perilaku nyata, state UI lengkap (empty, loading, error, indeterminate progress), tema gelap/terang keduanya terpasang, `prefers-reduced-motion` dihormati, dan eksternal link ditangani dengan `shell.openExternal`. Temuan terbesar ada di copy writing (em dash), kontras warna teks sekunder, satu token CSS yang tidak terdefinisi (bug nyata), dan beberapa celah aksesibilitas form.

## Temuan

### HIGH (Hard Gate)

**1. R-02: 43 em dash (—) dalam copy yang tampil ke user**
Sebaran: CreateView 13, SettingsView 8, GuideView 7, TroubleshootView 7, HomeView 3, SendView 3, App.tsx 1 (tooltip), QueuePanel 1. Daftar baris lengkap di Lampiran A.
Alasan: Hard Gate melarang karakter em dash di teks apa pun; ganti dengan koma, titik dua, atau tanda kurung.
Catatan: jika gaya em dash ini pilihan sadar sang owner (bagian dari voice), itu override yang harus dicatat satu baris di DESIGN.md. Tanpa catatan itu, anggap perlu diganti.
Ada juga 6 em dash di komentar kode (SettingsView 1, VerifyView 1, styles.css 3, jobs.ts 1); di luar scope R-02 (bukan UI copy), boleh ikut dirapikan saat menyentuh file yang sama.

**2. R-25: token `--text-faint` gagal WCAG AA di kedua tema untuk teks normal**
Terhitung: dark 3.68:1 sampai 4.14:1, light 2.67:1 sampai 3.08:1 (syarat 4.5:1 untuk teks normal; semua pemakaiannya berukuran 10.5-12px, jadi bukan "large text"). Selain itu `update-badge` tema light 4.16:1 (teks 11px di atas tint accent).
Lokasi terdampak: field hints, input placeholder, sidebar footer, tool-detail, home-eyebrow, t-rule terminal, queue-step-label, format-ext.
Perbaikan: naikkan `--text-faint` (dan bila perlu `--text-dim`) sampai lulus 4.5:1 di kedua tema, atau jangan pakai faint untuk teks di bawah 14px. Kandidat nilai: dark sekitar `#8b949e` ke atas, light sekitar `#6e7781` ke bawah (verifikasi ulang setelah dipilih).

**3. R-34 / C-4: token `--panel` dipakai tapi tidak pernah didefinisikan (bug nyata)**
`styles.css:760` (`background: var(--panel)` pada `.queue-panel`) dan `styles.css:903` (color-mix pada track `.queue-progress`). Token tidak ada di `:root`, `[data-theme='dark']`, maupun `[data-theme='light']`, jadi deklarasi menjadi invalid at computed-value time: background queue panel jadi transparan dan track progress indeterminate tidak terlihat di kedua tema.
Perbaikan: definisikan `--panel` di kedua blok tema (mis. dark `#11141a`, light `#eef0f4`), atau ganti referensinya ke `--bg-inset`.

**4. R-39: label form tidak terasosiasi secara programatik dengan kontrolnya**
Tidak ada satu pun `htmlFor`/`id` di seluruh renderer, dan label tidak membungkus input (pola `<div class="field"><label>...</label> ... <input>`). Screen reader tidak mengumumkan label untuk: PathField (semua pemakaian), input Console address, Port, PS5 title, Volume label, select Inode density, Path override.
Perbaikan: tambahkan `id` pada input dan `htmlFor` pada label (PathField bisa generate id dari label), atau bungkus kontrol dengan label.

**5. R-32: indikator fokus input lebih lemah dari ring global**
`input[type='text']:focus, input[type='number']:focus, select:focus` memakai `outline: none` + perubahan `border-color` 1px. Spesifisitasnya mengalahkan ring `:focus-visible` global (2px accent), jadi pengguna keyboard hanya melihat pergeseran warna border 1px. Untuk tema brand "kenyamanan", konsistensi ring fokus sekaligus memperkuat aksesibilitas.
Perbaikan: hapus `outline: none` dan biarkan ring `:focus-visible` berlaku juga untuk input/select (border accent boleh tetap sebagai penanda tambahan).

**6. R-39: kontradiksi ARIA pada pemilih accent color**
`SettingsView` memakai `role="radiogroup"` untuk container swatch, tapi anak-anaknya adalah button dengan `aria-pressed` (semantik toggle). Radiogroup seharusnya berisi `role="radio"` + `aria-checked`, seperti yang sudah benar dilakukan komponen `Segmented`.
Perbaikan: samakan pola dengan Segmented (`role="radio"`, `aria-checked`), atau ganti container menjadi div biasa tanpa role radiogroup.

**7. R-37: tidak ada arahan desain yang tercatat (DESIGN.md) di repo**
Desain eksisting tidak punya sumber direction; dials (ENERGY/RHYTHM/MOTION) tidak pernah dideklarasikan. Owner sudah memberi direction lisan di sesi ini (modern minimalist, clean, professional; kenyamanan dan kemudahan).
Perbaikan: tulis DESIGN.md dari jawaban owner (owner adalah penulisnya, agen hanya memformat), termasuk dials. Saran awal dari direction tersebut: ENERGY 1 / RHYTHM 1 / MOTION 1 (kalm, nyaman, minim gerak), cocok dengan karakter UI sekarang yang sudah tenang.

### MEDIUM (Purpose-Gate)

**8. R-06: label mikro uppercase + letter-spacing sebagai default tanpa alasan tertulis**
`.card h2` (13px, uppercase, 0.06em), `.queue-head h2` (11px, uppercase, 0.08em), `.home-eyebrow` (11px, uppercase, 0.08em). Pola "uppercase dengan tracking lebar" adalah salah satu tanda slop ketika tanpa purpose; pada 11px ditambah warna faint (lihat temuan 2) justru mengurangi keterbacaan, dan terasa "teknis/keras" dibanding voice brand yang nyaman dan mudah.
Perbaikan: ganti ke sentence case (mis. "Build readiness", "Queue") atau tulis alasannya satu baris di DESIGN.md kalau uppercase memang identitas yang diinginkan.

**9. R-30 / R-20: palet adalah nilai hex GitHub Primer apa adanya**
`--accent` green/blue/purple/orange/pink, `--ok`, `--warn`, `--err` di kedua tema semuanya token Primer (#3fb950, #58a6ff/#0969da, #bc8cff/#8250df, #f0883e/#bc4c00, #f778ba/#bf3989, #d29922/#9a6700, #f85149/#cf222e). Hasil akhirnya bagus dan konsisten, tapi identitas visualnya "aplikasi GitHub", bukan milik SM+ Toolbox. Sebagai Quality Lock ini nominal LOW, tapi dinaikkan ke MEDIUM karena berbenturan langsung dengan tujuan brand owner (identitas sendiri, nyaman, mudah dikenali).
Perbaikan: turunkan palet sendiri dari jiwa brand (mis. tetap hijau tapi bukan hijau GitHub, atau geser hue ke arah yang lebih hangat/tenang), lalu catat alasannya di DESIGN.md. Tidak harus besar; cukup jadi milik sendiri.

### LOW (Quality Locks)

**10. R-26 / R-39: link in-app "Settings" di HomeView memakai `href=""`**
HomeView baris 160-165: `<a href="" onClick={preventDefault}>` untuk pindah view. `href` kosong adalah destinasi mati secara semantik (middle-click dan "copy link address" mengarah ke kosong).
Perbaikan: ganti jadi `<button>` yang di-styling seperti link, karena fungsinya memang toggle state (pindah view), bukan navigasi dokumen.

**11. R-14: empat action tile di Home identik ukuran dan komposisinya**
Pola copy-paste cards (icon + title + desc, ukuran seragam). Defensible sebagai nav grid aplikasi desktop dan tile primary sudah dibedakan lewat border accent, jadi ini watch item, bukan keharusan.
Perbaikan (opsional): beri variasi hirarki (mis. tile utama lebih besar) atau catat alasan satu baris di DESIGN.md kalau grid seragam memang pilihan.

## Yang sudah baik (tidak perlu diubah)

- C-2 / R-26: tidak ada tombol mati; semua kontrol punya handler nyata; link eksternal ditangani `shell.openExternal` + guard `will-navigate`.
- R-27: state UI lengkap: detecting (Home), loading (Settings), empty (queue), error (callouts), indeterminate progress, busy/disabled states.
- R-17 / R-18 / R-36: tidak ada statistik palsu, testimoni fiktif, atau klaim keamanan yang difabrikasi; angka yang tampil berasal dari data nyata (ukuran file, jumlah file, versi tool).
- R-16: copy spesifik dan jujur; tidak ada buzzword ("seamless", "revolutionary", dsb.).
- R-21 / R-34 (selain temuan 3): tema dark/light/auto dengan token lengkap dan preset accent; kedua mode konsisten.
- R-19: motion kecil dan bertujuan (120-200ms, tanpa bounce/float berlebihan), cocok untuk tool desktop; `prefers-reduced-motion` dihormati (styles.css:1975).
- R-32 (sebagian): semua kontrol adalah elemen native; ring `:focus-visible` global ada; `aria-expanded` pada accordion; `aria-label` pada tombol ikon; `html lang`, `<title>`, landmark sidebar/main ada.
- R-03: aplikasi desktop dengan `minWidth: 940` (src/main/index.ts:41), jadi tidak ada risiko overflow mobile; ini konteks yang tepat untuk tool desktop.
